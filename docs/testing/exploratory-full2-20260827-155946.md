# Exploratory Functional Test #2 — FuelPass (ResourceFlow)

**Scope:** Bug-hunting full pass (PDF / relationship / 5xx focus) · **Date:** 2026-08-27 · **Artifact ID:** exploratory-full2-20260827-155946
**Goal:** Find errors like the recently-fixed `PdfGeneratorController` (legacy `empleado`→`personal` rename) across **all** flows, plus verify the fixed PDF flow works.

---

## 1. Executive Summary

A second full-pass exploration of FuelPass was executed against the seeded + prior-test database, using the full-admin profile. **2 real functional defects were found and reproduced**, both in the same family of "domain/HTTP error path" bugs as the PDF fix:

- **H-01 — Lote "Generar" returns HTTP 500 with the raw Laravel error page** when the lote's recorded combustible is not present for its centro de costo. `GenerateLoteController` only catches `InvalidArgumentException`, but `StoreTicketService` throws the domain exception `CombustibleNotFoundInEstacion`, which escapes as an unhandled 500 instead of a friendly flash.
- **H-02 — Tickets "Consumir" is unusable from the UI.** `tickets/gestion.blade.php` nests a `<form>` inside a `<tr>` (invalid HTML). Browsers eject the row cells from the form, so the `litros_consumidos` input ends up **outside any form**; pressing "Consumir" submits only the CSRF token and always bounces with a validation error. The backend endpoint itself works when the field is included.

**The headline PDF fix is verified working**: `/pdf/{ticket}` → HTTP 200 `application/pdf` (no 500, `personal` relationship OK), `/pdf/{nonexistent}` → clean 404, `/digitalTicket/{id}` renders 200, lote `imprimir`/`pdf` and both auditoría timeline-PDF endpoints all return 200 `application/pdf`.

Everything else passed: Auth, Dashboard, Centros, Personal, Vehículos, Recursos (create >1000 L now **accepted** — the old 999.99 cap was raised), Tickets create/edit/delete, Lotes happy-path (generate → "Se crearon 1 tickets"), Reportes CSVs, Auditoría timelines + CSV, Usuarios/Gestión, Roles, Logout + protected redirect.

**Per-flow status: 12 OK, 1 PARTIAL (G-tickets: only the Consumir action is broken).** No other HTTP >= 400, no `Call to undefined relationship`, no `RelationNotFoundException`, no column-not-found errors anywhere.

## 8. Prioritized Findings

### High
- **H-01 — Lote "Generar" returns HTTP 500 (unhandled domain exception).** If a lote's `tipo_combustible` has no Bolsa/Recurso for its `centro_costo`, `StoreTicketService` throws `CombustibleNotFoundInEstacion` which **escapes** `GenerateLoteController` (it catches only `InvalidArgumentException`). Result: raw Laravel 500 error page (`APP_DEBUG` stack dump) exposed to the operator instead of an inline error. Reproduced deterministically via the UI (`/lotes/2/generar`). *Evidence: J-lotes/11, HTTP scan.* **Fix suggestion:** catch the domain exceptions (`CombustibleNotFoundInEstacion`, plus any `Combustible`-family and `InvalidArgumentException`) and redirect back with a Spanish flash; audit all DDD ticket/consume controllers for the same missing catch (they follow the same pattern).
- **H-02 — Tickets "Consumir" cannot work from the UI (invalid `<form>` inside `<tr>`).** `resources/views/tickets/gestion.blade.php` wraps the row's `<td>`s inside a `<form>`. Browsers treat this as invalid nesting and hoist the form sibling to the row, ejecting the cells — confirmed live: `input[name=litros_consumidos]` reports `closest('form') === null`. Clicking "Consumir" therefore POSTs only `_token`, and the request always comes back with a validation error (`litros_consumidos` required). Consumption is impossible through the UI; the backend endpoint is fine (direct POST with the field consumed 20 L and moved the ticket to status `utilizado`). *Evidence: G-tickets/05 + 13, DOM inspection.* **Fix suggestion:** move the `@csrf` + inputs **outside** the `<form>`; use a `<form>` around the action cell only (`<td><form>…Consumir</form></td>`) with the hidden input inside it, or refactor to a per-action form placed in the cell.

### Medium
- **M-01 — New Recursos still stored/labeled "Inactivo" (unresolved from previous run).** Resources created this session (ids 6, 7, 8) were persisted with `activo` empty and displayed as "Inactivo", excluded from the "Bolsas de Combustible" accumulators until a ticket is emitted against them. Same behavior as the previous report (M-01).
- **M-02 — Tickets list link habit:** `/tickets/gestion?id=` forces the admin branch re-query by `request('id')`; not a bug, but the route `/tickets/gestion/{id?}` ignores its own path segment (controller only reads the query `id`). If a user manually opens `/tickets/gestion/7` (no query), the ticket list stays empty. Minor correctness/consistency gap in the route contract.

### Low
- **L-01 — Two logout submit buttons on every page (previous L-03, re-verified).** The sidebar "Cerrar sesión" and header "Salir" are both `button[type=submit]` inside logout forms. During automated probing, a generic `click('button[type=submit]')` resolved to the header logout and silently killed the session (`POST /logout`) — a real trap for scripted/assistive interaction and duplicate affordance. Recommend giving content form buttons explicit `name`/`id` and removing one logout entrypoint.
- **L-02 — Unlocalized validation strings.** Fortify's "These credentials do not match our records." is shown in the Spanish UI (A-auth/02). Same class as previous L-01. Resources now accept >1000 L, so the old `litros` message is no longer reachable.
- **L-03 — Invalid input `type="telefono"` on the Personal form** (treated as plain text by the browser) — carried over from the previous report.
- **L-04 — No `data-testid` on rows/actions** — flows were scripted via text/href selectors (low automability of the lists).

## 9. Non-invasive Recommendations

1. **H-01**: catch `CombustibleNotFoundInEstacion` (and sibling domain exceptions) in `GenerateLoteController` (and audit `StoreTicketController`, `ConsumeTicketController` for the same pattern) → redirect back with a Spanish error; never expose the debug stack.
2. **H-02**: fix the markup in `tickets/gestion.blade.php` so each consumption `<form>` lives inside a `<td>` (self-contained), guaranteeing `litros_consumidos` is submitted with the Consumir action; regression-test with a real browser (assert the submitted body contains `litros_consumidos`).
3. **M-01**: same as previous run — decide the intended `activo` lifecycle for newly ingested recurs; surface incoming stock in the accumulator regardless of the flag.
4. **L-01**: scope/logic for automation: keep helper content-submit selectors that exclude `form[action*="logout"]`; product-side, scope submit handling per form.
5. Non-invasive observability additions: `data-testid` on row actions; Spanish locale for validation/error messages.

## 10. Residual Risks and Next Steps

- **Residual risks**
  - The consume action was validated against the backend directly (direct POST) because the UI is broken; re-test the UI flow after H-02 is fixed.
  - H-01 was demonstrated with one mismatched pairing; the same exception class may surface in other ticket-emitting entry points (manual ticket creation with a stale datalist pair).
  - Permission-denied (403) flows still untested (admin has all permissions).
  - Responsive/mobile sidebar not exercised at small viewports.
- **Next steps**
  - Create a limited-permission profile and exercise role-restricted routes (`/reporte`, `/auditoria`, `/usuarios/gestion`) expecting 403.
  - After the H-02 markup fix, run a focused Playwright check that the Consumir submission includes `litros_consumidos`.
  - Decide and implement the H-01 catch scope, then re-run the J flow's broken-pair scenario expecting a flash error instead of 500.
